# コード監査 / Code audit — 2026年9月19日

アプリケーション全体を三つの観点（編集画面、管理画面、共通ライブラリと認可）から
調査した結果である。修正済みのものと、未修正で残しているものを分けて記載する。

## 修正済み / Fixed

### 認可 — 他人のデータに手が届いた

| 箇所 | 内容 |
|---|---|
| `people/[personId]/actions.ts` | `fieldId` / `valueId` / `historyId` / `recordId` / `versionId` がクライアントから届いた値のまま使われ、`personId` との関係が確認されていなかった。自分の `personId` と他人の `valueId` を組み合わせると、他人の項目のロック解除・確認済み化・復元ができた。`src/lib/auth/ownership.ts` を新設し、すべての id をその持ち主まで解決してから処理する。 |
| 同上 | 権限判定に使う `sectionCode` もクライアント由来だった。技術者が編集可能なセクション名を名乗り、編集できないセクションの項目を書き換えられた。`fieldId` から実際のセクションを引く方式に変更。 |
| `loadHistoryAction` | `valueId` の持ち主を確認せずに履歴を返していた。 |
| `/people` | 役割の確認がなく、技術者・デモ閲覧者が全員分の一覧を開けた。 |
| `submitForReviewAction` | 権限確認がなく、閲覧のみのデモ利用者が確定済みの版を「確認待ち」に戻し、管理者全員に通知を送れた。確定済みの版は差し戻せないようにした。 |
| `restoreVersionAction` | 他人の版 id を渡すと、その内容が別人のシートに複製された。 |
| `/api/files/[key]` | ログインしていれば誰のPDF・写真でも取得できた。鍵から持ち主を解決して照合する。併せて `..` を含む鍵で保存領域の外に出られないようにした。 |
| 編集画面 | 補足資料のセクション（配属検討用の情報・備考）が技術者本人にも表示されていた。出力側は拒否している内容である。 |

### 画面の動作

| 箇所 | 内容 |
|---|---|
| `field-editor.tsx` | 入力欄の値がサーバーの更新に追従せず、再生成・復元・保存後に古い文章を表示し続けた。その状態で保存すると新しい内容を古い内容で上書きした。 |
| `admin/audit` | `?page=abc` で `NaN` が Prisma に渡り、画面全体が500になっていた。 |
| `admin/glossary` | 既存の語を追加し直すと、確認なしに別表記・補足を空で上書きしていた。重複を報告するようにした。検索が日本語列だけ前後の空白を除去せず、Excelから貼り付けると0件になっていた。 |
| `admin/fields` | 取得元設問の入れ替えがトランザクション外だったため、途中で失敗すると取得元が空のまま残り、以後その項目は黙って空で生成されるようになっていた。重複コードも除去する。項目コードが空白のみでも作成でき、削除手段のない行が残った。 |
| `admin/import` | 事前確認と実際の取り込みで対象者の照合条件が違い、「新規」と表示された行が既存の人物を上書きすることがあった。取り込み履歴が更新されない問題も修正。 |

| すべてのサーバーアクション | 本番ビルドでは送出した例外の文面が伏せられるため、「この項目はロックされている」等の説明が利用者に届かなかった。`src/lib/actions/result.ts` を経由して結果として返す。 |

## 未修正 / Known, not yet fixed

優先度順。いずれも影響範囲を確認済みだが、今回の修正には含めていない。

1. **手動追加したレコードの一括生成が内容を消す** — 画面から追加したレコードには
   `sourcePrefix` がないため取得元が解決できず、生成が空の結果を返して入力済みの
   文章を上書きする。手入力の項目は影響を受けない。修正は生成側で「取得元が
   一つも無い場合は書き込まない」とするのが筋である。
2. **同一ファイル内の重複メールアドレス** — 2行目が既存扱いになり、1行目の回答を
   上書きする。事前確認でも重複として表示されない。
3. **取り込み中のレコード作成エラーが握り潰される** — `createRecord(...).catch(() => undefined)`
   がすべての失敗を無視するため、学歴・インターン等が丸ごと欠けても成功と表示される。
4. **`runImport` がトランザクションでない** — 途中で失敗すると、件数だけ記録された
   取り込み履歴と、部分的に取り込まれた人物が残る。
5. **PDFボタンの出し分け** — 現在の版が下書きでも、過去に確定した版があれば出力
   エンドポイントは応じる。画面は「確定版のみ」として無効化しており、確定済みの
   シートを再ダウンロードできない。
6. **Shift_JIS のCSV** — 検証がなく、文字化けしたまま取り込まれる。設問コードは
   ASCII なので対応付けは成立し、氏名等だけが化ける。
7. **期限切れセッション行が削除されない** — 動作上の問題はないが、増え続ける。
8. **`FIELDS_NEVER_SENT_TO_AI` は項目コードで判定している** — 送信内容は取得元の
   設問コードから組み立てられるため、管理画面で送信対象の項目に A-1-1 等を
   割り当てると、氏名や生年月日がAIに送られうる。現在の定義ではそうなっていない。
