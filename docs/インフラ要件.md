# インフラ要件のご回答

ご質問4点について、実測値でお答えします。数値は本システムを実際に動かして
計測したもので、見積もりではありません。

---

## 1. PostgreSQL は使えるか

**はい。問題ありません。** 本システムのデータベースは PostgreSQL を前提に
設計しており、現在ご契約の RDS（db.t3.small / 20GB）にそのまま載ります。

- 必要なのは PostgreSQL 15 以上です。RDS の現行バージョンで満たしています。
- 歩数計アプリと同じインスタンス内に、**別のデータベース**を作って同居させる
  形で構いません（`CREATE DATABASE skillsheet;`）。相互に影響しません。
- 保存されるのはテキストが中心で、容量はごくわずかです。5名で数MB、
  100名に増えても 100MB に届きません。20GB のうち実質使いません。
- 画像とPDFは**データベースには入れません**（後述3）。

---

## 2. アプリの所要メモリ・ディスク

### メモリ

| 状態 | 実測 |
|---|---|
| 通常の画面操作（アプリ本体） | 約 150〜300 MB |
| **PDF出力中（一時的）** | **これに加えて 0.5〜1.0 GB** |

PDF出力だけが突出します。本システムは画面表示とPDFを**同一のHTMLから**
生成しており（見た目が必ず一致するようにするため）、その変換に Chromium を
使います。1件あたりの所要時間は約1.6秒、その間だけメモリを大きく使い、
終われば解放されます。

**ここが唯一の懸念点です。** t3.medium は 4 GiB で、すでに歩数計アプリと
旧スキルシートアプリが動いています。空きが 1.5 GB を下回っている場合、
PDF出力の瞬間にメモリ不足で他のアプリを巻き込んで落ちる恐れがあります。

ラトゥーリ様に**現在の空きメモリ**（`free -m` の available 値）をご確認
いただけますでしょうか。そのうえで、

- **空きが 1.5 GB 以上** → 現行の t3.medium のままで問題ありません。
- **空きが 1.5 GB 未満** → 次のいずれかをご検討ください。
  1. スワップ領域を 2GB 追加する（費用ゼロ。PDF出力が数秒遅くなる程度）
  2. t3.large（8 GiB）に変更する（月額が上がります）

同時に複数名のPDFを出力すると、その分だけ重なります。5名程度の運用であれば
順番に出力されるため、1件分を見込んでいれば足ります。

### ディスク

| 内訳 | 実測 |
|---|---|
| アプリ本体（ビルド済み） | 約 150 MB |
| 実行に必要なライブラリ | 約 400 MB |
| PDF変換用 Chromium | 約 600 MB |
| **小計** | **約 1.2 GB** |

20 GiB のうち 1.2 GB を使います。他の2アプリの使用量次第ですが、
`df -h` で**空きが 3 GB 以上**あれば余裕をもって収まります。

## 3. 写真とPDFの容量

**ご認識の訂正が1点あります。RDS には保存しません。** データベースに
バイナリを入れると、バックアップとリストアが重くなり、容量単価も割高です。
**EC2 のディスク**に保存する方式にしています（設定でS3へ切り替え可能です）。

### 1名あたりの実測値

| 種類 | 1件あたり | 備考 |
|---|---|---|
| スキルシートPDF | 約 0.8 MB | 5ページ・日本語フォント埋め込み込み |
| 補足資料PDF | 約 0.5 MB | 1ページ |
| 顔写真 | 0.3〜2 MB | 上限 5 MB で制限しています |

PDFは**出力するたびに履歴として保存**します（いつ誰が出した版かを追えるように
するためです）。1名につき5回出力したとして、

> **1名あたり 約 8 MB。余裕をみて 10 MB。**

| 人数 | 必要容量 |
|---|---|
| 5名（当面） | **約 50 MB** |
| 30名 | 約 300 MB |
| 100名 | 約 1 GB |

当面の5名であれば **50 MB**、現在のディスクで全く問題ありません。

## 4. 現状の構成で足りないもの

**結論として、追加購入が必要なものはありません。** 確認が必要なのは1点だけです。

| 項目 | 判定 |
|---|---|
| PostgreSQL（RDS） | **足りています。** 新規データベースを1つ作るだけです |
| ディスク（EC2 20GiB） | **足りています。** アプリ1.2GB＋データ50MB |
| S3 | **不要です。** EC2のディスクで足ります。将来100名規模になり、かつ 冗長性を重視される場合に検討で十分です |
| メモリ（EC2 4GiB） | **要確認。** PDF出力時に一時的に最大1GB必要です（上記2） |

### ご確認いただきたいこと

1. `free -m` の available 値（PDF出力の余裕があるか）
2. `df -h` の空き容量（3GB以上あるか）
3. RDS に新しいデータベースを作ってよいか

2 が不足する場合はスワップ追加（無償）で対応できます。1 が不足する場合のみ、
インスタンスの変更をご相談させてください。
