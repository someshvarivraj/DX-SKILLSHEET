## 1. 日本語組版として守っていること

英語向けのブラウザ既定値のままでは日本語は正しく組めない。次の4点を明示的に
指定している。

| 指定 | 何のためか |
|---|---|
| `line-break: strict` | 禁則処理。行頭に `、` `。` `）` `」` が来ないようにする |
| `overflow-wrap: anywhere` | 長い英字（URL・メールアドレス・設問コード）が枠からはみ出すのを防ぐ。日本語の途中では改行しない |
| `font-feature-settings: "palt"` | 見出しの字詰め。全角文字の間隔が空きすぎて見えるのを直す |
| `word-break: auto-phrase` | 見出し・項目名を文節で折り返す。対応ブラウザのみ有効（Chromiumは対応） |

あわせて、**斜体は使わない**。日本語に斜体の習慣はないため、`em` などは
`font-style: normal; font-weight: 700` に戻し、強調は太字で行う。

行間は **1.7〜2.0** の範囲を使う。漢字は仮想ボディいっぱいに字面があるため、
同じ級数でも英文より詰まって見え、Tailwind既定の行間では窮屈になる。

### 行頭の「、」と空行について

生成文の途中に空行が入り、次の行が `、` で始まる不具合があった。原因は組版
ではなく**データ側**で、モックAIが数値を拾う正規表現 `\d+(?:\.\d+)?\s*[%％]?`
の末尾の `\s*` が、回答と回答の区切りである改行2つまで飲み込んでいた。

```
"…[C-1-1] N2\n\n[C-1-4] IELTS 7.0…"  →  数値: ["1", "1", "2\n\n", "1"]
                                      →  "数値は1、1、2\n\n、1である。"
```

対策は3段構えにしてある。どれか1つでも通れば正しく印刷される。

1. `src/lib/ai/mock.ts` — 拾った数値から空白を除去する（根本原因）
2. `src/lib/style/text.ts` の `normaliseJapanese()` — 空行を畳み、行頭禁則
   文字の直前の改行を削除する（保存時）
3. `sheet-document.tsx` の `toDisplayLines()` — 同じ処理を表示時にも行う
   （**修正前に保存済みの値も、再生成せずに正しく印刷される**）

回帰テストは `tests/ai-mock.test.ts` と `tests/style.test.ts` にある。

## 2. 揃え方（中央寄せと左寄せの使い分け）

**見出しは中央寄せ、項目名と本文は左寄せ**にしてある。2つは役割が違う。

| 対象 | 例 | 揃え | 理由 |
|---|---|---|---|
| 節の見出し帯 | 個人情報 Personal Information | 中央 | 節の名前であり、行全体を占める。折り返さないので中央寄せが安定する |
| レコードの見出し | インターンシップ 1 | 中央 | 同上 |
| 節名の縦ラベル | 志向 | 中央 | 同上（志向の欄） |
| 項目名 | プログラミング言語 | **左** | 値の横に並び、折り返すことがある |
| 値・本文 | C、C++、Python | **左** | |

項目名を左寄せにしているのは、中央寄せだと折り返したときに2行目だけが中央に
寄って体裁が崩れるためである。

```
中央寄せ（不可）          左寄せ（採用）
┌──────────────┐        ┌──────────────┐
│ プログラミング言 │        │ プログラミング言 │
│      語        │        │ 語             │
└──────────────┘        └──────────────┘
```

**中央寄せを足すときは、その欄が絶対に折り返さないと確認できる場合に限ること。**

### 実装上の注意

見出しを中央寄せにしている規則は、セレクタを省略せずに書いてある。

```css
.sheet table.sheet-table > tbody > tr.band > th { text-align: center; }
```

セルの共通規則が `.sheet table.sheet-table > tbody > tr > th`（クラス2・要素4）
であるため、`.sheet tr.band th`（クラス2・要素2）と短く書くと詳細度で負けて
左寄せのままになる。短くしないこと。

## 3. 節ごとの色

節を色で見分けられるようにしてある。配色は
`SECTION_COLOURS`（`sheet-document.tsx`）の1か所で定義している。

| 節 | 系統 | アクセント |
|---|---|---|
| 個人情報 | 紺 | `#3D5A8A` |
| 志向 / キャリアアップについて | 青緑 | `#2E6F66` |
| 学歴 | 青 | `#2F6BA8` |
| 技術スキル | 臙脂 | `#9E4468` |
| インターンシップ | 緑 | `#3E7A52` |
| プロジェクト | 紫 | `#67589B` |
| 日本語能力 | 赤茶 | `#A94F46` |
| 研究業績 | 鉄紺 | `#46688C` |
| 興味ある分野 / 日本企業について | 琥珀 | `#A0662C` |
| 配属検討用の情報 | 灰青 | `#4E6A7A` |
| リーダーシップ・課外活動 | 苔緑 | `#6B7A3E` |
| その他 | 灰 | `#5C6472` |

方針は3つ。

- **彩度を抑える。** A4に印刷し、白黒コピーも取られる。鮮やかな色は
  グレースケールで潰れて読めなくなる。
- **近い節は同系色にする。** 14節すべてを別の色にすると虹のようになり、
  業務書類として落ち着かない。関連する節はまとめてある。
- **色は帯だけに使う。** 本文と項目名は常に黒に近い色で、背景は白か淡い灰。
  可読性を色に依存させない。

節を追加したときは `SECTION_COLOURS` に足す。書き忘れても既定の灰色が使われ、
表示は壊れない。

## 4. 文字の大きさ

| 対象 | 値 | 備考 |
|---|---|---|
| シート本文 | 10.5pt | 日本語のビジネス文書の標準。以前は9.5ptで小さすぎた |
| 節の見出し帯 | 11.5pt | |
| 氏名 | 13pt | |
| 画面の本文 | 15px | |
| ボタン | 14px・高さ36px以上 | 長時間の操作でも押しやすい大きさ |

画面側はTailwindの級数そのものを `@theme` で1段上げてあるため、
`text-xs` などを使っている箇所は自動的に大きくなる。**個別に `text-[11px]`
のような直接指定を書かないこと。** 級数を一括で調整できなくなる。

## 5. 操作画面で気をつけていること

- **すべてのボタンに `title` で説明を付ける。** 「確定する」が何を意味するか
  （PDFが出せるようになる／全項目の確認が必要）は、押す前に分かる必要がある。
- **次にすべきことを文で出す。** ツールバーは状態に応じて「未確認が何件ある」
  「確定できる」「確認を依頼する」を文章で表示する。バッジの色から推測させない。
- **できない操作は押せなくする。** 確定前のPDFボタンは無効化し、理由を
  `title` に書く。押させてからエラー画面を出すより分かりやすい。
- **キーボード操作でも焦点が見える。** `:focus-visible` で輪郭を出している。

## 6. 体裁を変えたときの確認方法

画面のスクリーンショットだけでは、印刷時の改ページや背景色の再現は確認できない。
PDFまで出して見ること。特に次の2点は印刷でしか現れない。

- 節の見出し帯がページ末尾に取り残されていないか
  （`break-after: avoid` で抑止している）
- 背景色が出ているか（`print-color-adjust: exact` が必要）
