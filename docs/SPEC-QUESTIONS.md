# 仕様書についての確認事項 / Questions on the specification

仕様書（IITスキルシート生成システム_仕様書_0910.pdf）とフォーム定義（create_iit_form_2026.gs）を
突き合わせた結果、確認させていただきたい点をまとめました。

すべての項目に「現在の実装」を書いています。ご回答をお待ちする間も作業が止まらないよう、
いったん妥当と思われる方法で実装してあります。ご指示があればその通りに直します。

While reviewing the specification against the form definition we found the points below.
Each one states what we have implemented for now, so work is not blocked while we wait
for an answer. Anything can be changed once you decide.

---

## A. スキルシートに載せる項目について / Which questions appear on the sheet

### A-1. 同じ設問が2か所に指定されている / The same question feeds two different fields

**内容**
仕様書6.2節の「希望職種」と6.7節の「興味ある分野」は、どちらも取得元が **G-1-1A〜C** と
書かれています。このままだと、スキルシートの2か所にまったく同じ内容が並びます。

見本のスキルシートを見ると、「希望職種」には「ソフトウェア開発、組込み系・ロボティクス開発…」
のような内容が入っており、これは **I-1-3（日本企業でやってみたい仕事）** に近いように見えます。

**確認したいこと**
どちらかの取得元を変更すべきでしょうか。たとえば次のどちらかが考えられます。

- 希望職種 = I-1-3、興味ある分野 = G-1-1A〜C
- 希望職種 = G-1-1A〜C、興味ある分野 = G-1-4（将来目指したい役割）

**現在の実装**
仕様書の記載どおり、両方とも G-1-1A〜C にしています。画面から取得元を変更できるので、
ご指示があればプログラムの修正なしで直せます。

---

### A-2. フォームにあるが6章に配置の指定がない設問 / Questions collected but not placed

次の設問はフォームで収集していますが、仕様書6章のどの項目にも割り当てられていません。

| 設問 | 内容 |
|---|---|
| A-1-3 | 性別 |
| A-1-5 | 現在の居住地 |
| B-1-6 / B-2-6 / B-3-5 | 成績（CGPA・Percentage） |
| C-1-2 | 次回のJLPT受験予定 |
| C-1-3 | 日本語の学習歴 |
| H-1-1 | 学生団体・プロジェクトリーダー等 |
| H-1-2 | 発表・受賞・チームマネジメント経験 |
| J-1-1 | 備考 |
| J-1-2 | GitHub・ポートフォリオリンク |
| J-1-3 | 趣味、興味あること |

**確認したいこと**
これらはスキルシートに載せない前提でしょうか。特に次の2点が気になっています。

1. **趣味（J-1-3）**：仕様書9.1節の文体の表と9.3節（趣味欄の体言止め）で「趣味」欄の
   書き方が定められています。9章で書き方が決まっているのに6章に項目がないため、
   載せる想定だが記載漏れではないかと考えています。
2. **成績（CGPA）**：対訳辞書に「CGPA（累積成績平均）」が登録されており、
   「日本のGPAとは尺度が異なる」という注記まであります。辞書にあるということは、
   どこかに表示する想定ではないでしょうか。

**現在の実装**
「リーダーシップ・課外活動」と「その他（趣味・GitHub・備考）」という2つのセクションを
作り、**既定では非表示**にしてあります。表示するご判断であれば、画面のチェックボックス1つで
出せます。性別・現在の居住地・成績・JLPT学習歴は、いまは項目を作っていません。

### A-3. 空欄の扱いが2か所で異なる / Two different rules for empty fields

- 仕様書 **8.3節**：「項目名は残したうえで、内容を空欄にして出力すること」
- 仕様書 **6.4節**：「該当項目がすべて『使用経験なし』の場合、その欄は非表示にしてください」

技術スキル欄について、この2つが逆のことを言っているように読めます。

**確認したいこと**
技術スキル欄（CAD・CAE・電気制御・材料分析など）が「使用経験なし」のみだった場合、
項目名だけ残して空欄にするのか、行ごと消すのか、どちらでしょうか。

**現在の実装**
6.4節が技術スキルについての個別の指示だと解釈し、**空の項目は行ごと非表示**にしています。
文章系の項目（インターンの内容など）が空の場合も同様に非表示です。

## B. 日本語能力の欄について / The Japanese ability section

### B-1. 面談での所見はPDFに出力しますか / Is the interview note printed?

仕様書6.10節の冒頭に「スキルシートに掲載するのは取得資格と時期、およびスコアから生成した
説明文の2つだけ」とありますが、同じ節の表には「面談・面接での所見」という手入力欄もあります。

**確認したいこと**
「面談・面接での所見」はPDFに出力する項目でしょうか。それとも画面上だけで参照する
メモでしょうか。

**現在の実装**
PDFに出力する設定にしています（画面から1クリックで非出力に変えられます）。
各スコアは指示どおりPDFには出力していません。

---

### B-2. 説明文はAIを使わず規則で生成しています / The description is rule-based

仕様書10章のとおり、日本語力の説明文は**AIを使わず**、得点区分から規則にしたがって
生成しています。同じ入力からは必ず同じ文章が出ます。

合否の判定は次の表を使っています（10.1節の記載どおり）。ご確認ください。

| レベル | 合格点 | 区分ごとの基準点 |
|---|---|---|
| N1 | 100 | 3区分それぞれ19点 |
| N2 | 90 | 3区分それぞれ19点 |
| N3 | 95 | 3区分それぞれ19点 |
| N4 | 90 | 言語知識・読解38点、聴解19点 |
| N5 | 80 | 言語知識・読解38点、聴解19点 |

総合点が合格点に達していても、いずれかの区分が基準点を下回る場合は不合格として扱い、
説明文でもその点に触れます。

## C. 運用に関わる点 / Operational points

### C-1. 社員番号とメールアドレスの対応表 / Linking employee numbers

仕様書15章にもあるとおり、フォームはメールアドレスを収集しており、社員番号は別管理です。

**確認したいこと**
社員番号とメールアドレスの対応表を、CSVなどでいただけますでしょうか。
いただければ取り込み時に自動で紐付けます。

**現在の実装**
社員番号は画面から手入力する項目にしています。対応表をいただければ自動化します。

---

### C-2. 顔写真のサイズ / Photo dimensions

**確認したいこと**
アップロードする顔写真に、決まった寸法はありますでしょうか。
見本のスキルシートでは縦長（おおよそ3:4）で表示されています。

**現在の実装**
JPEGを受け付け、表示時に縦長（96×120ピクセル相当）に収めています。
指定の寸法があれば、アップロード時にその比率で切り抜けるようにします。

---

### C-3. 確定とPDF出力の順序 / The order of "finalise" and "export"

- 仕様書 **11.1節**：「PDFを出力できるのは、ステータスが『確定』の版のみ」
- 仕様書 **5.8節**：「PDFを出力するとき、出力前に自動で保存を実行すること」

保存が新しい版を作る仕組みだと、出力直前の保存で「下書き」の版ができてしまい、
11.1節と矛盾します。

**現在の実装**
次のようにしています。ご確認ください。

1. 編集中はつねに「下書き」の版に保存される（保存のたびに項目単位の履歴が残る）
2. 「確定する」を押すと、その版が「確定」になる。未確認の項目が残っている場合は
   確定できず、どの項目が未確認かを一覧で表示する
3. PDFは「確定」の版から出力する
4. 確定後にもう一度編集すると、確定版はそのまま残り、新しい「下書き」の版が作られる

---

### C-4. 提出先ごとの設定は1組で足りますか / One display preset or several?

仕様書5.5節に「現時点で保持する設定は1組で構いません。ただし将来『A社向け』『B社向け』の
ように複数保存したいという要望が想定される」とあります。

**現在の実装**
データの持ち方は最初から複数組に対応する形にしてあります（表示フラグと表示順を
レコード本体とは別のテーブルに分離）。画面には現在「既定」の1組だけを出しています。
第1段階で複数組の画面も必要でしたらお知らせください。

## D. 第3段階（本人による更新）について / Phase 3 — self-service

仕様書14章では第3段階として「採用者本人が自分のスキルシートを修正し、管理者が確認して
確定する機能」を予定されています。佐野様のご返信で「これが最も重要な目的」と伺ったため、
**第1段階から作り込んでいます**。

**現在の実装**
- 利用者の権限を4種類にしています：管理者／営業／技術者（本人）／閲覧のみ（デモ）
- 技術者本人は「インターンシップ」と「プロジェクト」の欄だけを編集でき、
  新しい現場での経験を自分で追加できます
- 編集後に「確認を依頼する」を押すと、状態が「確認待ち」になります
- 管理者が内容を確認して「確定」します
- 版管理と項目単位の履歴は最初から入っているため、あとから作り直す必要はありません

**確認したいこと**
1. 本人が編集できる範囲は「インターンシップ」と「プロジェクト」で合っていますでしょうか。
   （例：趣味や、日本語の学習状況なども本人に任せますか）
2. 本人が編集したとき、管理者に**メールで通知**する必要はありますでしょうか。
3. 将来、日本人社員のスキルシートにも広げるとのことでしたが、その場合は
   「英語から日本語へ翻訳する」処理が不要になります。項目定義の「処理区分」を
   「手入力」や「転記」に変えるだけで対応できる作りにしてあります。

## E. ご参考：毎年のフォーム改訂への対応 / How the yearly form change is absorbed

ご要望の中心である「フォームが変わってもアプリを作り直さなくてよいこと」については、
次のようにしています。

1. **フォーム定義スクリプト（.gs）から設問一覧を自動で読み取ります。**
   来年 `create_iit_form_2027.gs` をいただいたら、コマンドを1回実行するだけで
   設問一覧（設問ID・回答形式・選択肢・グリッドの行と列）が更新されます。
   2026年版では113問すべてを正しく読み取れることを確認済みです。

2. **どの設問がスキルシートのどこに入るかは、画面上の設定です。**
   プログラムの中には書かれていません。設問が増えたら行を追加し、
   設問IDが変わったら取得元を書き換えるだけで、改修も再デプロイも不要です。

3. **取り込み時に、どの項目にも割り当てられていない設問を「未割当」として一覧表示します。**
   フォーム改訂時の対応漏れを防ぐためです。

4. **AIへの指示文（生成プロンプト）も画面から変更できます。**
   出力の傾向を調整するのに開発者を介す必要はありません。
